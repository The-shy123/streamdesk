# 保存记录的列表、查看与选择回放

更新：2026-10-19。新增 C++ 程序 `streamdesk_records`。它直接浏览指定目录中的正式录制文件和未完成文件，不建立数据库，也不移动、修改或删除记录。

## 最短使用流程

在项目根目录按 README 构建后执行：

```sh
./build/cmake-debug/streamdesk_records build --interactive
```

默认查看指定目录以及下一层子目录，因此能发现现有 `build/demo-*/numeric.sdr`。也可以把 `build` 换成自己保存记录的目录。若还没有记录，先运行 `python3 tools/demo.py --record`；演示结束会输出浏览命令。

列表每一行包括：编号、状态、文件字节数、相对于所选目录的路径。编号从 1 开始，按相对路径排序。启动后输入命令并回车：

| 命令 | 功能 |
| --- | --- |
| `list` | 再次显示当前列表和最近查看得到的状态 |
| `show 1` | 完整校验第 1 条记录，查看来源、流、会话、条数、起止 seq 和前 5 条以内样例 |
| `replay 1` | 打开第 1 条记录，进入暂停状态的回放控制 |
| `refresh` | 重新发现新增/删除的文件并显示新列表；编号可能改变 |
| `help` | 显示命令提示 |
| `quit` / `exit` | 退出浏览器 |

进入回放后沿用已有命令：`next` 单步、`play` 播放、`pause` 暂停、`resume` 继续、`status` 查看进度、`stop` 停止。停止或播放完成后自动返回记录列表的命令入口，可以再 `show` 或 `replay` 另一条。回放内的 `quit` 等同于 `stop`，返回列表；在列表内 `quit` 才退出整个程序。

浏览器默认回放间隔为 100 ms，可使用 `--interval-ms 0..1000` 改变固定间隔。Ctrl+C 在列表或回放中都退出整个浏览器；输入 EOF 也能结束，不遗留子进程或后台读取线程。

例如一段连续操作：

```text
show 1
replay 1
next
status
stop
show 2
replay 2
play
```

示例中的编号以实际列表为准，记录少于两条时不要使用 2。文件名带空格、中文、引号时仍使用编号，无需手工拼接路径。

## 非交互命令

```sh
# 仅列出，随后退出
./build/cmake-debug/streamdesk_records build

# 查看第 1 条的详细信息，随后退出
./build/cmake-debug/streamdesk_records build --show 1

# 完整顺序回放第 1 条，无人工延时
./build/cmake-debug/streamdesk_records build --replay 1 --interval-ms 0

# 只查看指定目录内文件，不进入子目录
./build/cmake-debug/streamdesk_records build --depth 0
```

每次非交互命令会重新生成列表；若两次调用之间目录变化，编号也可能变化。需要稳定选择时使用交互模式，在同一列表快照内操作。

## 状态与文件变化

| 状态 | 含义 |
| --- | --- |
| `unchecked` | 发现了 `.sdr` 文件，尚未完整读取，不能据此判断可回放 |
| `ready` | 最近一次打开时通过完整校验；每次再打开仍重新检查 |
| `incomplete` | `.sdr.partial` 尚未完成或尚未发布，可能仍在写入，不能回放 |
| `invalid` | 文件超出大小上限，或打开时发现格式/完整性错误 |
| `unavailable` | 文件已消失、无法访问、为符号链接或不是普通文件 |

列表发现文件时只检查文件类型、大小与后缀，避免启动就把所有大文件全部读一遍。查看与回放复用 `RecordingReader`，完整预检通过后才给出可信元数据或输出记录；损坏文件不会先展示一个“正常前缀”。未完成文件只显示文件级信息与原因，不伪造已保存条数。

交互编号绑定当前快照中的相对路径，目录出现新文件时不会悄悄改变旧编号；刷新会明确打印新列表。它不是持久化记录 ID。同一路径被替换时，以重新打开和校验的实际文件为准；旧 `ready` 状态不免除校验。浏览或回放时不要并发修改记录内容或目录结构。删除/损坏的选中项报错后仍可继续查看其他记录。

## 实现与边界

- `scan_recordings` 默认向下 1 层，可选 0..3 层；只收集 `.sdr` 与 `.sdr.partial`，每次最多枚举 10000 个目录项、收集 512 条候选。超限明确失败，不返回看似完整的截断列表；子目录无法读取时显示警告。
- 不跟随子目录符号链接；候选符号链接与特殊文件保留为不可用条目。每次选择重新检查路径组件，避免选中项被换成链接后继续打开。
- `inspect_recording` 在完整校验后最多保存 5 条预览；文件内容不作为列表缓存常驻内存。单文件仍受原来 16 MiB / 10000 条限制。
- 浏览器与独立回放命令共享 `apps/cli/replay.cpp`，没有复制另一套播放状态。每次进入回放都创建新的读取器和进度，退出后释放，切换文件不会沿用旧进度。
- 共享命令输入对象只读到当前命令的换行，不一次取走下一批命令；这样 `stop` 后紧接的 `show` 不会被回放层吞掉。命令长度最多 128 字节。
- 路径和错误中的换行、ESC 等控制字节会转义显示，不能把文件名伪装成另一条终端输出；路径不会交给 shell 执行。

当前完成本地文件列表、详情与编号选择回放；删除/重命名、持久化索引、搜索筛选、排序切换、GUI、HTTP 与录制区间控制不在本轮实现范围。
