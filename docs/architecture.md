# 数据流与生命周期

```text
Python 固定数值源（独立进程）
  → 回环 TCP / 4 字节网络序长度 + JSON
  → Boost.Asio 单连接接入（一个 io_context 线程）
  → FrameParser（最多一个正文输出）
  → decode_numeric（拥有字符串的模型、字段校验）
  → NumericWorker（一个工作线程；任务数/字节有界）
  → 有限终端预览 + 汇总
  → 可选 JSONL 核对文件 → streamdesk_inspect → StreamCore 校验与展示
  → 可选 RecordingWriter → .partial → 成功收尾发布 .sdr
  → RecordingReader 全文件预检 → streamdesk_replay 顺序读取与播放控制
```

StreamCore 仅依赖标准库、线程库与私有 nlohmann/json。Boost 只属于网络适配。C++ 服务、检查程序、回放与浏览工具通过公开头文件及 CMake 链接目标调用核心；没有直接包含实现文件。

## 所有权与容量

解析器拥有部分正文；交付 string 后调用者拥有正文。JSON 解码复制必要字符串到 NumericMessage，临时 JSON 和正文销毁不影响模型。服务端保留一个待提交 unique_ptr；仅 Accepted 后移交工作线程，Busy/Stopped/TooLarge 不消耗输入。处理回调只在调用期间借用 const 引用，任务处理后释放对象，再归还容量。

队列限制同时覆盖等待及正在执行的任务：默认最多 32 项、262144 字节。字节数按内部生成的规范化 JSON 大小计算，不由外部虚报；这是明确的输入表示计量，不声称等于 C++ 堆占用。网络另外持有一个 4096 字节读取缓冲、最多 65536 字节正文及一个待提交模型，不保存无限输出列表。

Busy 时保留一个待提交对象、暂停继续读取，使用可取消异步定时器重试，最多等待 1 秒，超时明确失败。网络线程不等待条件变量、不写核对文件、不 join。工作异常增加 failed 并保存限长错误；继续处理后续已接受任务，不伪装全部成功。

## 停止与异常

正常 EOF 必须在完整消息边界，随后拒绝新任务、排空已接受任务。SIGINT/SIGTERM 关闭接入、取消定时器并请求停止；事件循环结束后由唯一控制线程 join。已解码但尚未接受的对象在停止时丢弃并计数 discarded_pending，状态为 stopped，不能冒充完整采集。未读网络字节在主动停止时不承诺处理。

只有一源一流一次会话，首条 seq 可为任意 uint64；后续必须连续，来源/流/会话不可中途切换。重复、缺口和未知消息明确失败。首版示例没有自动重连或补发，连接恢复也不会意味着补齐缺失记录。

整体运行默认 30 秒、最大可配 300 秒，输入空闲/半包最多 3 秒；单次最多 10000 条、核对文件最多 16 MiB。终端最多预览前 20 条并报告最后一条和汇总；减少预览不改变完整核对文件。sum 是有限 double，累加溢出作为可观察处理失败，不输出 Infinity 伪装有效统计。

## 展示范围与缺失能力

当前使用命令行界面：服务端终端展示实时前 20 条，结束后检查程序使用同一核心库核对 JSONL。没有 Qt 页面、HTTP/WebSocket 或桌面连接按钮；桌面客户端尚未实现。JSONL 仍仅用于核对。2026-10-18 增加独立 .sdr 录制格式、固定条数区间与本地回放控制，见 recording.md；历史数据库和 HTTP 控制未实现。

没有公网服务、数据库、用户权限、图像/行情、性能结论或部署。其他平台没有运行证据。Mac 通过不能扩展为跨平台产品通过。

## 一键演示编排

`tools/demo.py` 组织服务、固定源、检查程序，以及 `--record` 启用的录制和回放，不增加新的数据处理实现。它请求系统分配本机端口，等待实际 READY 后发送，检查进程退出、服务器统计、全部字段与顺序及检查程序结果；每次建立独立输出目录。正常与失败都有日志，失败清理自身子进程并返回非零。产品处理仍由 C++ 核心和服务执行。

## 保存与回放的线程边界（2026-10-18）

RecordingWriter 在服务 READY 前创建并独占保留目标的 .partial；只有工作线程追加记录。网络控制线程结束 io_context 并 join 后才检查结果与 finish，二者不并发操作文件。任一处理错误或异常终止都不发布完整文件；首个 I/O 异常保留，后续排空任务不会覆盖根因。

RecordingReader 在构造时做有界的整文件预检，然后回到开头，每次 next 交付一条拥有数据的模型。CLI 控制循环串行处理状态与读取，无后台预取；暂停后不继续 next，停止后不继续输出。独立命令可以重新打开文件；记录浏览器在返回列表后新建读取器，旧回放状态不会进入新记录。完整格式、上限和状态见 [recording.md](recording.md)。

## 记录浏览与共享回放（2026-10-19）

`scan_recordings` 只做有界发现，返回按相对路径排序的列表快照。`inspect_recording` 与 `open_catalog_recording` 每次重新检查并调用 RecordingReader 完整预检；详情最多保留五条样例，列表没有全文缓存。编号只在本快照内有效，refresh 后明确替换列表。

`streamdesk_records` 与 `streamdesk_replay` 通过内部 StreamDeskCli 目标共用回放函数。控制台输入与信号处理留在 apps/cli，不进入核心目录模型。共用的 CommandInput 逐行消费输入；回放的读取器、计数和状态按调用作用域释放，因此返回后选择新文件不会沿用旧进度，也不会丢失下一个浏览命令。细节见 [records.md](records.md)。
